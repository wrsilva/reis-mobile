# Applying the UX laws and visual rules on mobile

The [Laws of UX guides](laws-of-ux/GUIDE.md) and the [app UI design guide](app-ui-design/GUIDE.md) were written with web examples: CSS, JSX, Tailwind, hover states and desktop navigation. The laws hold on a phone; many of the examples and a few of the rules do not. Read this file before applying either guide to Flutter, Android, iOS, React Native or Kotlin Multiplatform code, and write each fix in the project's own toolkit and theme.

## What changes on mobile

| The guides say | On mobile |
|---|---|
| Hover states (`:hover`, checklist item 6, "contextual tooltips on hover", hover transforms) | Touch has no hover. Specify pressed, focused (hardware keyboard, Switch Access, Full Keyboard Access), selected and disabled states. Hover exists only with a pointer on iPad, Android tablets and Chromebooks, as an addition. |
| Touch targets `min-h-11`, "44x44px" | iOS: 44 × 44 pt (Human Interface Guidelines). Android and Material: 48 × 48 dp. Measure the hit area, not the visible glyph. |
| Jakob's Law: left sidebar or top nav, search top-right, profile top-right, submit bottom-right | Bottom tab bar or navigation bar with three to five destinations; top app bar or navigation bar with back at the leading edge; system back (the Android back button and gesture, the iOS swipe from the leading edge); the primary action at the bottom of the screen or, on Android, a floating action button. Where iOS and Android differ, follow each platform. |
| `transition: all 200ms`, CSS skeleton animations | The toolkit's animation APIs, and no motion when the user turned it off (Reduce Motion, removed animations). |
| `px`, `rem`, `gap-2` / `gap-8` | dp on Android and logical pixels in Flutter, pt on iOS, density-independent numbers in React Native, all from the theme's spacing scale. |
| "Maximum 4 font sizes and 2 font weights" (the anti-pattern list in the same guide allows 3 weights) | A heuristic for one screen, not a limit. Use the platform's type roles so text scales with the user's setting: Dynamic Type text styles on iOS, the Material 3 type scale on Android and Flutter, `allowFontScaling` left on in React Native. |
| Secondary text at 60–70% opacity | Check the resulting contrast in light and dark mode: 4.5:1 for body text and 3:1 for large text (WCAG 2.2), with [mobile-accessibility](../../mobile-accessibility/SKILL.md). |
| Section padding of 80–96 px (160 px on larger screens), text containers under 600 px | Landing-page values. A phone screen uses the theme's spacing scale; a reading width around 600 dp applies to the expanded width of tablets and foldables. |
| Cognitive Bias: "1,234 users", "3 people viewing", "was $99, now $49" | Only real, current data. Invented counts, fake countdowns and made-up reference prices are deceptive patterns, and both stores' review policies prohibit misleading users. |
| Implementation notes: React, Tailwind, Lucide, Recharts, `backdrop-blur`, a 375 px baseline | Only for HTML prototypes. Production UI uses the project's toolkit, theme, icon set and chart library, and is checked on the smallest and largest supported devices, not one width. |
| Thumb zone: primary actions in the bottom third | Phones held in one hand. On tablets and in landscape, follow the platform layout: navigation rail, top toolbar, split view. |
| Keyboard shortcuts (Productivity conventions) | Hardware keyboards on iPad, Android tablets and Chromebooks; phones rarely have one. |

Where the Laws of UX guides mention the commands `/laws-of-ux review` and `/laws-of-ux checklist` or the skills `laws-of-ux-review` and `laws-of-ux-checklist`, read [laws-of-ux/review.md](laws-of-ux/review.md) and [laws-of-ux/checklist.md](laws-of-ux/checklist.md). A finding's fix is code in the project's stack, at `path:line`, not CSS.

## The laws in each stack

Check each API against the versions in the project's lock file and deployment target before writing it.

| Law and need | Flutter | Native Android | Native iOS | React Native | Kotlin Multiplatform |
|---|---|---|---|---|---|
| **Fitts's Law**: a target large enough to hit | `kMinInteractiveDimension` (48); `MaterialTapTargetSize.padded`; `ConstrainedBox(constraints: BoxConstraints(minWidth: 48, minHeight: 48))` for custom widgets | Compose `Modifier.minimumInteractiveComponentSize()` (48 dp); Views `android:minWidth="48dp"` and `android:minHeight="48dp"` or a `TouchDelegate` | SwiftUI `.frame(minWidth: 44, minHeight: 44)` with `.contentShape(Rectangle())`; UIKit a 44 pt frame or an overridden `point(inside:with:)` | `Pressable` with `hitSlop`, or `minWidth`/`minHeight` of 44 on iOS and 48 on Android | Compose Multiplatform `Modifier.minimumInteractiveComponentSize()`; the iOS values when the iOS UI is SwiftUI |
| **Doherty Threshold**: feedback within 400 ms | `CircularProgressIndicator`, `LinearProgressIndicator`; optimistic state in the state owner (BLoC, Riverpod, Provider); a placeholder with the content's shape | Compose `CircularProgressIndicator`, `LinearProgressIndicator`; Views `CircularProgressIndicator` and `LinearProgressIndicator` from Material Components | SwiftUI `ProgressView()`, `.redacted(reason: .placeholder)` for skeletons; UIKit `UIActivityIndicatorView` | `ActivityIndicator`; optimistic updates with TanStack Query `onMutate` when the project uses it | Loading state in the shared ViewModel's `StateFlow`, rendered by the host UI |
| **Aesthetic-Usability** without hover: a visible pressed state | `InkWell`; `ButtonStyle(overlayColor: WidgetStateProperty.resolveWith(...))` | Compose Material components ripple by default; custom targets `Modifier.clickable(interactionSource, indication)` and `collectIsPressedAsState()` | SwiftUI a `ButtonStyle` reading `configuration.isPressed`; UIKit `UIButton.Configuration` with `configurationUpdateHandler` | `Pressable` with `style={({ pressed }) => …}` and `android_ripple` | Compose Multiplatform as Compose |
| **Proximity**: tight within a group, wider between groups | `Column(spacing: 8)`, `SizedBox(height: 24)`, spacing values in a `ThemeExtension` | Compose `Arrangement.spacedBy(8.dp)`; Views dimension resources (`@dimen/space_2`) | SwiftUI `VStack(spacing: 8)`; UIKit `UIStackView.spacing` and `setCustomSpacing(_:after:)` | `gap`, `rowGap`, `columnGap` (React Native 0.71+) from a spacing scale | Compose Multiplatform `Arrangement.spacedBy` |
| **Cognitive Load**, **Tesler's Law**: progressive disclosure | `ExpansionTile` | Compose `AnimatedVisibility` behind a toggle | SwiftUI `DisclosureGroup` | A toggled section with `accessibilityState={{ expanded }}` | Compose Multiplatform `AnimatedVisibility` |
| **Hick's** and **Miller's Laws**: few visible choices | `NavigationBar` with three to five destinations, `PopupMenuButton`, `SegmentedButton` | Compose `NavigationBar`, `DropdownMenu`, `SingleChoiceSegmentedButtonRow` | SwiftUI `TabView`, `Menu`, `Picker` with `.pickerStyle(.segmented)`; `UITabBarController` moves tabs beyond five into More on iPhone | React Navigation bottom tabs (no automatic More: keep five or fewer), a menu from the project's UI library | Compose Multiplatform `NavigationBar`, `DropdownMenu` |
| **Goal-Gradient**: progress through steps | `LinearProgressIndicator(value: step / total)`, `Stepper` | Compose `LinearProgressIndicator(progress = { step / total.toFloat() })` (Material 3 1.2+; earlier versions take a `Float`) | SwiftUI `ProgressView(value: Double(step), total: Double(total))` | A `View` sized to the fraction, with `accessibilityRole="progressbar"` and `accessibilityValue={{ min: 0, max: total, now: step }}` | Compose Multiplatform `LinearProgressIndicator` |
| **Jakob's Law**: platform navigation and back | `NavigationBar`; `CupertinoPageRoute` for the iOS swipe back; `PopScope` to intercept back | Compose `NavigationBar`, `TopAppBar`, `BackHandler`, or `PredictiveBackHandler` for the predictive back animation | SwiftUI `NavigationStack` (swipe back included) and `TabView` | `@react-navigation/native-stack` for native back behavior, bottom tabs | Compose Multiplatform draws Material on iOS too: check how the project's navigation library handles the iOS swipe back, or host that flow in SwiftUI |
| **Peak-End Rule**, transitions: motion the user can turn off | `MediaQuery.disableAnimationsOf(context)` | `Settings.Global.ANIMATOR_DURATION_SCALE` (0 when animations are removed) | SwiftUI `@Environment(\.accessibilityReduceMotion)`; UIKit `UIAccessibility.isReduceMotionEnabled` | `AccessibilityInfo.isReduceMotionEnabled()` | The host setting through `expect`/`actual` |
| **Selective Attention**, typography: hierarchy that still scales | `Theme.of(context).textTheme`, `MediaQuery.textScalerOf(context)` | Compose `MaterialTheme.typography` in `sp`; Views `TextAppearance.Material3.*` in `sp` | SwiftUI `.font(.body)` and `@ScaledMetric`; UIKit `UIFont.preferredFont(forTextStyle:)` with `adjustsFontForContentSizeCategory = true` | `allowFontScaling` (on by default); `maxFontSizeMultiplier` only where a layout truly breaks | Compose Multiplatform `MaterialTheme.typography` in `sp` |

## Reviews and checklists on mobile code

- **Score per screen, on its states.** Run [the review](laws-of-ux/review.md) on one screen or flow and on its loading, empty, error and success states, not on a folder of components.
- **Evidence is mobile evidence.** Cite the widget, composable, view or component at `path:line`, the resolved theme value and the device size. A static screenshot cannot prove a hit area, a pressed state or reduced motion; mark those as checks to run on a device.
- **Platform first.** A law never overrides a platform convention that users of that platform rely on: an Android screen keeps system back and Material patterns, an iOS screen keeps the navigation bar and swipe back, and a cross-platform screen states which behavior differs per platform.
- **Checklist item 8** becomes 44 × 44 pt on iOS and 48 × 48 dp on Android; **item 6** checks pressed and focused states instead of hover.
